## Decisions (agreed 2026-11-16)
1. **Backend first.** The cases API does not exist, so it is built (C1-C7) before the UI,
   which then uses generated types only: no mock layer with hand-written types.
2. **Names follow the code, not the spec**: the channel is `/copilot/*` (engine decision
   23), not `/web/*`; the inspection API is `/admin/cases/*` (every channel, admin key).
   A case is the problem (`problems`, `case_id`); a session is the web channel's thread
   (`session_id`, generated by the client), linked to its case in `conversation_links`.
3. **One commit per step**, brief first, stop after each (the repo's rule).
4. **No title column**: `title` is derived from `what` (cut to 80 characters), null until
   `what` is recorded. No migration for it.
5. **No `get_case_summary` endpoint**: the structured summary would repeat `get_case`; the
   UI builds it from that response.
6. **The trace records the proposed phase** of each `propose_transition` call (a phase name,
   never content; null in older traces), so a rejected transition shows its target and
   error code. Done before `get_case` (C3) so the trace shape is final when it is exposed.
7. **Messages carry their turn number** in `get_case`: each committed turn writes exactly
   one user message, one reply and one trace (`commit_turn`), so the API numbers them and
   the UI never pairs by guessing.
8. **The AI summary is stored** (agreed 2026-11-16), one per case, regenerated only on
   request: `case_summaries` (migration 0004) with `source_version`; `get_case` returns it
   with `stale` when the case version moved on. Writing it never bumps the case version (so
   it cannot cause `409 case_changed`). Generating it is the only billed path; tests use the
   fake provider and no real call is made without the user's OK. Migrations 0003 and 0004
   reach the Neon dev branch only with the user's OK.
9. **No e2e test**: the UI has no e2e tooling (Vitest + MSW only), and Playwright would be
   a heavy addition.
