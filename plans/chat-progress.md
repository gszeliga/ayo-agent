## Decisions (agreed 2026-11-16)
1. **Backend first.** The cases API does not exist, so it is built (C1-C8) before the UI,
   which then uses generated types only: no mock layer with hand-written types.
2. **Names follow the code, not the spec**: the channel is `/copilot/*` (engine decision
   23), not `/web/*`; the inspection API is `/admin/cases/*` (every channel, admin key).
   A case is the problem (`problems`, `case_id`); a session is the web channel's thread
   (`session_id`, generated by the client), linked to its case in `conversation_links`.
3. **One commit per step**, brief first, stop after each (the repo's rule).
4. **No title column**: `title` is derived from `what` (cut to 80 characters), null until
   `what` is recorded. No migration for it.
5. **No `get_case_summary` endpoint**: the structured summary would repeat `get_case`; the
   UI builds it from that response.
6. **The trace records the proposed phase** of each `propose_transition` call (a phase name,
   never content; null in older traces), so a rejected transition shows its target and
   error code. Done before `get_case` (C3) so the trace shape is final when it is exposed.
7. **Messages carry their turn number** in `get_case`: each committed turn writes exactly
   one user message, one reply and one trace (`commit_turn`), so the API numbers them and
   the UI never pairs by guessing.
8. **The AI summary is stored** (agreed 2026-11-16), one per case, regenerated only on
   request: `case_summaries` (migration 0004) with `source_version`; `get_case` returns it
   with `stale` when the case version moved on. Writing it never bumps the case version (so
   it cannot cause `409 case_changed`). Generating it is the only billed path; tests use the
   fake provider and no real call is made without the user's OK. Migrations 0003 and 0004
   reach the Neon dev branch only with the user's OK.
9. **No e2e test**: the UI has no e2e tooling (Vitest + MSW only), and Playwright would be
   a heavy addition.
10. **Turns are paged apart from the case** (agreed 2026-11-17, C4 brief): `get_case`
    carries the header, facts, annotations and actions only. Messages and traces come
    from `GET /admin/cases/{case_id}/turns` (C5), one item per turn (user message, reply,
    trace), so the UI loads older turns as you scroll. This adds a step: delete, summary
    table and summary generation move to C6-C8.
11. **`chunk_id` is exposed** in the trace's retrieved chunks (an id, never text), next to
    `doc_id`, the document title and `document_deleted` (agreed 2026-11-17).
12. **The admin view is cross-tenant**: no tenant parameter on `/admin/cases/*`
    (agreed 2026-11-17).
13. **Turns page oldest first with `offset`** (agreed 2026-11-17, C5 brief), in the usual
    `Page` shape. Turns are only added at the end, so offsets never move while chatting
    (newest first would shift every page by one per new turn; a cursor would need a new
    page shape). The UI loads the latest with `offset = max(0, turns - limit)`, steps back
    by `limit`, and after a turn fetches `offset = turns`. Pages are chosen by the SQL
    (`order by turn_no limit offset`), not by sorting in code.
14. **A turn missing its user message or reply is a server error** (500,
    `MissingTurnMessage`), not a null field: `commit_turn` writes both with the trace, so
    a gap is a bug.
15. **Deleting a case frees its session** (agreed 2026-11-17, C6 brief): the link goes with
    the case (`on delete cascade`), so a later message on the same `session_id` opens a new
    case; no tombstone. A turn running during the delete fails its version check and
    answers `409 case_changed`, storing nothing.
16. **Summary storage** (agreed 2026-11-17, C7 brief): `case_summaries` keyed by
    `problem_id` (one per case, cascade on delete) with `content`, `source_version`,
    `model`, `prompts_version`, `total_tokens`, `cost`, `created_at`. The API exposes
    `content`, `model`, `generated_at`, `source_version` and `stale` (source version below
    the case's); tokens and cost are stored for cost tracking only. The upsert never
    replaces a summary made from a newer case version (racing generations: the later case
    wins). The summary prompt gets its own version string in C8.
17. **Summary generation** (agreed 2026-11-17, C8 brief): `409 case_empty` for a case with
    no turns (no call made); the model gets the whole case record and the latest
    `SUMMARY_MAX_MESSAGES` (40) messages; `SUMMARY_PROMPTS_VERSION` apart from
    `PROMPTS_VERSION`; `SUMMARY_MODEL` (unset: `LLM_MODEL`) and `SUMMARY_MAX_TOKENS` (800).
    Model failures map as in `/copilot` (the table moved to `errors.py`).
18. **Prototype first** (agreed 2026-11-17): the screen is settled on the U1 Artifact (T0)
    before any UI code, as U1 and U12 were. It is a reference, not code to port.
19. **Read-only cases**: one from another channel (`web_session_id: null`) and a closed one
    (the API answers `409 case_closed`) open with the input disabled and the reason shown.
20. **Hypotheses as the API has them**: the State tab lists hypotheses, then discarded ones
    (a discard is its own event, not linked to its hypothesis; a note says so), the
    validated cause and the evidence. No "confirmed" group: that is the validated cause.
    The facts are `what`, `where`, `since`, `standard` (the spec's "impact" does not exist).
21. **Navigation** (superseded 2026-11-27 by decision 1 in `plans/nav-progress.md`: Test
    chat is an ordinary tab, the divider stays, the group is "Knowledge base"): "Test chat" comes first, as an accent pill with an icon, then a divider
    and the "Knowledge" group (Documents, Search, Indexing settings). The landing page
    after connecting stays Documents; a link to `/chat/:caseId` survives the connect screen.
22. **Generating the AI summary asks first**: a dialog names the model and says the call is
    billed; Cancel or Generate.
23. **Retrieved chunks link to their document** (from the trace): the document opens on its
    Chunks tab at the chunk's page with the chunk outlined, and "Back to the chat" returns
    to the case. Chunk ids are random and replaced on every reprocess or replace, so the
    API resolves `chunk_index` at read time (C9): null when the chunk is no longer stored
    ("Changed since": the link opens the document), no link for a deleted document.
24. **Usage per case, one shape** (revised 2026-11-17 at the C10 brief): `LLMUsage`
    (`llm_calls`, prompt, completion and total tokens, `cost`; null when not reported)
    mirrors `llm/types.Usage` and is used three times: a turn's `trace.usage` (replacing
    its flat fields), the AI summary's `summary.usage` (one call, total tokens and cost
    only) and the case's `usage` (every turn plus the summary). A total sums what was
    reported, null only when nothing did; no extra counters. The chat header shows the
    case's cost and tokens; the Trace tab's "Case totals" shows cost, tokens and calls,
    with one line each for the turns and the summary. Latency, capped turns, retrieval
    failures and failed tool calls stay per turn. A regenerated summary replaces the
    stored one (its cost leaves the total); billing reports stay with OpenRouter (spend
    per key and model, generation ids in our logs). No cost column or sort in the list.
25. **Layout**: the cases list collapses to a rail (show, new conversation, a count); the
    inspector can be hidden and is a drawer on narrow screens. "Load earlier turns" is a
    button, not loading on scroll. Export (Markdown, JSON) fetches the turns not loaded
    yet first (reads only), so the file has the whole case.
26. **The list's filters live in memory** (agreed 2026-11-19, T1 brief): search, tenant,
    phase and state are page state, never in the URL (the search is content; the others
    would have to ride along on every case switch). They survive switching cases, not a
    reload. The page is a layout route, so the loaded pages survive too.
27. **"New conversation" comes with T3** (agreed 2026-11-19, T1 brief), where it works; the
    T1 rail shows only Show cases and the count.
28. **The collapsed list is not remembered** (agreed 2026-11-19, T1 brief): memory only.
29. **Refresh starts the turns over** (agreed 2026-11-19, T2 brief): it re-reads the case,
    then resets the turns to the latest page (computed from the case's new turn count when
    fetched); re-fetching the loaded offsets would miss turns added elsewhere.
30. **Scroll position** (agreed 2026-11-19, T2 brief, as browser scroll anchoring; built
    as a `flex-col-reverse` scroll area instead, which does the same in every browser,
    Safari included, without scroll code): opens at the newest turn, keeps its place when
    older turns load.
31. **Usage format** (agreed 2026-11-19, T2 brief): `$0.0021` below a cent, `$0.02` from a
    cent, `<$0.0001` for less; `850 tokens`, `12.3k tokens`, `1.2M tokens`.
32. **The header grows with its steps** (agreed 2026-11-19, T2 brief): T2 has Refresh only;
    Export, Delete and the inspector toggle come with T4 and T5. The tab title stays "Test
    chat" (a case title is content and tab titles reach the browser's history).
33. **`/chat/new` is its own route** (agreed 2026-11-19, T3 brief); the draft (`session_id`,
    tenant) lives in the chat page's memory, passed to the view as outlet context, never in
    the URL or location state. Without a draft it offers to start one.
34. **A turn is not cancelled by leaving its case** (agreed 2026-11-19, T3 brief): the cache
    updates run from the mutation's own options (they outlive the view); the alert, the
    text put back and the navigation of a new conversation run from `mutate`'s callbacks,
    only while the view is shown.
35. **The new conversation's tenant comes from `/admin/tenants`** (agreed 2026-11-19, T3
    brief): tenants with documents only; no free typing. The last one is remembered as a
    name in `localStorage` (`ayo.chat.last-tenant`).
36. **No trace chip yet** (agreed 2026-11-19, T3 brief): "Turn N" opens the trace in T4.
37. **T4 is split** (agreed 2026-11-23, T4 brief): T4a is the inspector's frame (column,
    toggle, drawer below 1024 px), State and Actions; T4b the Trace tab, case totals, chunk
    links and the "Turn N" chip. The inspector's hidden state and tab live in the chat
    page's memory (as decision 28); the drawer starts closed on each case.
38. **Resizable columns** (agreed 2026-11-23, after T4a: the inspector's content did not fit,
    and the user asked for the cases list too): both are resized by a handle on their inner
    edge, mouse and keyboard, with fixed limits and a share of the row; each width is kept in
    `localStorage` as a number only (the user's choice over memory only). The actions are
    cards instead of a table (the user's choice), so they fit any width.
39. **T5 is split** (agreed 2026-11-23, T5 brief): T5a is the Summary tab (structured summary
    from `get_case`, the AI summary and its billed-call dialog); T5b delete, export, the
    storage and axe tests, the README section and the final report.
40. **The summary model comes from `GET /admin/settings`** (agreed 2026-11-23, T5 brief: the
    user chose a backend step over naming it vaguely): a `copilot` section (`configured`,
    `model`, `summary_model` with `summary_model_source`, both prompt versions,
    `SUMMARY_MAX_TOKENS`; never the key), shown on the Settings page as a "Copilot" card.
    The schema keeps its name `IndexingSettings` and the nav its label. **Cached** (agreed
    the same day): the T5a dialog reads it from the `['settings']` query with its own
    `staleTime: Infinity` (it changes only with a restart), prefetched when the Summary tab
    opens; the Settings page keeps the default refresh (its document counts change).
41. **One pattern for both side panels** (agreed 2026-11-23 after the milestone, the user:
    the two collapse buttons were different and confusing; "mirrored rails" chosen from
    three mock-ups): each panel's toggle is an icon button at its inner top corner ("Hide
    cases" / "Hide inspector", `aria-expanded`, a tooltip); hidden, each leaves a rail on
    its page edge led by "Show cases" / "Show inspector"; the inspector rail has a button
    per tab and the API's overdue dot; narrow screens always show the inspector rail, which
    opens the drawer. The case header's "Inspector" button is gone.
42. **Fake vectors carry their own label** (agreed 2026-11-27, the user: "control del
    sellado" ranked the `gszeliga` README above the demo PRO-014 in an all-tenants search).
    The seed script embedded the demo documents with `FakeEmbedder` but stored the
    configured label `voyage-4/document/1024`, so search compared random vectors with real
    ones (on the dev branch, the demo chunks' mean similarity to their own siblings was
    -0.015, the README's 0.57). `embedder_descriptor` now takes the provider: `fake` gives
    `fake/document/<dimensions>` whatever the model; Voyage labels are unchanged (no
    reprocess of real documents). The seed script ingests with `embedding_provider="fake"`
    settings, so its label matches its vectors. The label still comes from the settings,
    not the embedder object (a per-embedder label would touch the protocol and every
    `current_configs` caller; not now). Option agreed: this (T6), then
    `--embedder voyage` on the seed script (T7, billed, opt-in).

## Final report (2026-11-23)

**Done.** The test chat and case inspector at `/chat` in the admin UI, and the API it needs.
- **Cases API** (C1-C10): `case_id` on the copilot endpoints; `GET /admin/cases` (filters,
  pages), `GET /admin/cases/{case_id}` (facts, annotations, actions with the API's
  `overdue`, the stored AI summary with `stale`, usage), `GET .../turns` (oldest first,
  paged by offset; each turn its messages and a content-free trace with chunk links
  resolved at read time), `DELETE` (cascade), `POST .../summary` (the only billed admin
  path; migration 0004 `case_summaries`), one usage shape (`LLMUsage`) throughout.
- **The chat** (T1-T3): the cases list (search kept out of the URL, tenant, phase, state,
  Load more, a collapsible rail), a case read-only with paging back and safe Markdown, the
  phase stepper and markers, sending with an in-flight state, errors by status with the
  text kept, new conversations with an in-memory session id.
- **The inspector** (T4a, T4b, T5a): State, Actions (cards), Trace (case totals, entries
  with tool calls, retrieved documents linking to their chunk and back, the "Turn N ·
  trace" chip), Summary (structured from the record; the AI summary behind a billed-call
  dialog naming the model from `GET /admin/settings`, cached); hideable, a drawer below
  1024 px, resizable like the cases list (widths kept as numbers).
- **Export and delete** (T5b): Markdown or JSON with every turn, made in the browser; a
  delete that says what goes.
- **Side steps:** query strings out of the access log; the schema revision logged at
  startup; the demo seed script (`scripts/seed_demo_cases.py`, seeded on the Neon dev
  branch); the copilot's models in `GET /admin/settings` with a Settings card.

**How.** Hand-written SQL in repeatable-read, read-only snapshots for every read; content
never logged (cases, queries, summaries); the UI built only on the generated types (no mock
layer, decision 1); TanStack Query caches per case, mutations for every billed or
destructive call (never retried), cache updates in the mutations' own options so they
survive leaving a view. Browser storage holds only the last tenant's name and two widths
(tested over a whole session).

**Tests.** UI: 488 (Vitest, Testing Library, MSW, axe on the chat page, its tabs and
dialogs). Backend: the cases API, the summary and the settings section covered in
`tests/api/` with every documented status triggered in the contract tests (1117 passed in
the suites run at the settings step). No real model or embedding call was made by any step
of this milestone. Bundle: main 127 KB gzipped (was 141 at the UI report, now with Vite's
current split), the chat's case view 11 KB and its page 4 KB, loaded on demand.

**Agreed deviations from the spec** are the decisions above (1-40); the main ones: no mock
layer and the backend first (1), names from the code (2), turns paged apart from the case
(10, 13), the stored AI summary with `stale` (8, 16) instead of an unsaved one, no e2e test
(9), the prototype first (18), chunk links with `chunk_index` resolved at read time (23),
one usage shape (24), the splits of T4 and T5 (37, 39), resizable columns (38), the summary
model from the settings (40).

**Not checked in a real browser by me.** Every UI step was verified only through jsdom
tests: layout, the resize handles, the drawer, scrolling to a chunk or a trace, the
download itself, and the look in dark mode need a manual pass (the demo cases cover each
state). The summary prompt has never run against a real model.
